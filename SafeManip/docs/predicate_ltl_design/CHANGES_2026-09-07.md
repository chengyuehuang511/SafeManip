# Changelog — 2026-09-07: framework simplification pass (no predicate/LTL behavior change)

Context: before starting work on tracking multiple concurrently-activating objects/fixtures
per LTL property (the "multi-object" `relevance.py` design), a structural review of
`monitor/`'s files surfaced several no-op indirection layers left over from this codebase's
origin as a fork of `SceneFlowLang` (`https://github.com/less-lab-uva/SceneFlowLang`) --
machinery that supported real multi-entity scene-graph binding upstream, but had never been
wired up for RoboCasa's flat privileged-info-dict pipeline and had decayed into dead code.
This session is a pure refactor: no `specs.py` formula, `predicates.py` semantics, or
threshold constant changed. Every step was verified against the real v19 corpus
(`monitor/output/v19_2026-09-05_claude_branch_recycle_object_role_ast_fix/`, 500 episodes
across 51 tasks) by re-running `monitor_rollout` and diffing the resulting `_monitor.json`
against the untouched v19 baseline byte-for-byte (ignoring only the `input_path` field, which
just echoes the invocation path). Final result: **500/500 episodes matched, 0 diffed.**

## 1. Merged `monitor/predicates.py` + `monitor/primitives.py` into one file

**Before:** `predicates.py` (top-level, ~500 lines) was a mechanical 1:1 mirror of
`primitives.py` (~850 lines) -- every one of `primitives.py`'s ~116 real predicate-lookup
functions had a same-named counterpart in `predicates.py` whose entire body was
`return partial(P.<name>, entity)`. No logic lived in `predicates.py` itself.

**Fix:** merged both into `predicates.py` (deleted `primitives.py`); real implementations
were renamed with a `_compute_` prefix (`object_stable` -> `_compute_object_stable`) to avoid
colliding with the public curry-wrapper of the same name, with every internal cross-reference
between real functions updated accordingly (e.g. `_compute_object_settled` calling
`_compute_object_supported`, `_compute_support_type_matches_object`, etc.). Updated the two
import sites (`monitor/monitor.py`, `monitor/run_monitor_on_privileged.py`) accordingly.

**Why this direction, not the reverse:** checked the actual upstream `SceneFlowLang` repo
(not just the local fork) -- it has no `robocasa/` subfolder and no split predicate/primitive
files at all; its single `SG_Primitives.py` plays the role of our merged file. Merging our two
files into one is *closer* to upstream's shape, not further from it.

## 2. Removed the `partial`/`SymbolicEntity` currying layer from predicate declarations

**Before:** every predicate in `predicates.py` was declared as
`def object_stable(entity=None): return partial(_compute_object_stable, entity)` --
deferring the call and attaching an unbound `SymbolicEntity` role placeholder
(`OBJECT`/`SUPPORT`/`FIXTURE`/`TARGET_OBJECT`), for `monitor.py`'s binding-enumeration
machinery to later substitute a concrete name into. `specs.py`'s `COMMON_PREDICATES` called
these wrappers (`R.object_stable(R.OBJECT)`) to build each property's predicate dict, and
`monitor.py`'s `alpha()`/`_evaluate_partial()` recursively unwrapped the resulting `partial`
tree at evaluation time.

**Problem:** this pattern exists upstream for a real reason -- `SceneFlowLang`'s own
`symbolic_properties.py` uses the identical `partial(P.relSet, entity, "isIn")` shape to build
genuine multi-step expression trees (e.g. `is_in_junction`: intersect two node sets, take the
size, check equality) that must stay unevaluated because they're evaluated against a real
scene graph later. Our RoboCasa predicates never compose anything -- each one is a single,
already-baked lookup by name (`sim/robocasa/predicates.py` did the real computation and
selection at extraction time) -- so the entire defer/unwrap apparatus was overhead with
nothing to defer. Every call already resolved `entity` to `None` in practice, since
`monitor.py`'s binding enumeration always collapsed to a single empty binding `{}` (see #3).

**Fix:** removed the ~116 curry-wrapper functions and the `OBJECT`/`SUPPORT`/`FIXTURE`/
`TARGET_OBJECT` placeholders from `predicates.py`, renaming `_compute_*` back to plain names.
`specs.py`'s `COMMON_PREDICATES` now references the function itself (`R.object_stable`, no
call) instead of a curried partial; `all_entities()` removed. `SymbolicProperty.__init__`
no longer calls `get_symbolic_entities()` (which required `predicate.args`/`.func`, i.e. a
`partial`) -- predicates are plain callables now. `monitor.py`'s `alpha()` calls each
predicate directly; `_evaluate_partial()` deleted.

## 3. Removed `monitor.py`'s dead binding-enumeration machinery; deleted `SymbolicEntity.py`

**Problem:** once (2) made `symbol_to_entities` always empty for every property,
`monitor.py`'s `_enumerate_bindings()` was provably 100%-dead -- it always took its
`not used_entities` branch and returned `[{}]`, never reaching the real per-object/fixture
enumeration code path (`_used_entities`, `_support_candidates`, `_uses_embedded_predicates`).
That real-enumeration code was already unreachable in practice before this session too (it
required `sim/robocasa/predicates.py` to *not* pre-embed all predicate values, which it
always does), but this made it unreachable *in principle*, not just in practice.

**Fix:** `step()` now uses a single `binding = {}` directly; deleted `_enumerate_bindings`,
`_used_entities`, `_support_candidates`, `_uses_embedded_predicates`, and the now-unused
`itertools`/`SymbolicEntity` imports. Deleted `monitor/SymbolicEntity.py` entirely (confirmed
via repo-wide grep it had no other callers). Also merged `monitor/SymbolicProperty.py` into
`monitor/symbolic_properties.py` (a genuine 1:1 pair -- the latter's only job was
instantiating the former's one class) and, while there, removed `SymbolicProperty.py`'s
already-fully-dead-and-unreachable `ConcreteProperty`/`make_concrete`/`make_blank`/
`get_concrete_entities`/`get_symbolic_entities`/`valid_mapping` (SceneFlowLang's real
scene-graph binding evaluator, confirmed via repo-wide grep to have zero callers anywhere
outside that one file).

## 4. Dropped the simulator-specific `RoboCasa` prefix from `monitor.py`'s class names

**Problem:** `RoboCasaSymbolicMonitor`/`RoboCasaProductState`/`RoboCasaTraceResult`/
`RoboCasaPropertyStatus` suggested the class bodies were robocasa-specific, but they aren't --
`alpha()`/`step()`/etc. only ever touch a generic `{"static": ..., "dynamic": ...}` dict shape
and a duck-typed `env`. Checked why the prefix exists: upstream `SceneFlowLang` already has
a plain `SymbolicMonitor` class (`SymbolicMonitor.py:50`); the robocasa fork's version was
presumably renamed to avoid colliding with that class when both lived in the same repo
(`SceneFlowLang/robocasa/monitor.py` vs. `SceneFlowLang/SymbolicMonitor.py`). That collision
reason doesn't apply here -- `SafeManip/monitor/` only has this one monitor.

**Fix:** renamed to `SymbolicMonitor`/`ProductState`/`TraceResult`/`PropertyStatus` (matching
upstream's own naming) in `monitor.py`, `run_monitor_on_privileged.py`, and `specs.py`'s
comments. Updated the class docstring to state explicitly what's genuinely simulator-agnostic
here vs. what's a robocasa-specific default (`properties=None` -> `build_all_properties()`).

## Known follow-up, not done this session

`monitor/predicates.py`'s remaining `obj`/`support`/`fixture` parameters and `_resolve_entity`
calls are themselves now no-ops (their resolved value is immediately discarded, `_ =
_resolve_entity(obj, kwargs)`, since nothing ever populates `bindings`/`obj`/`support`/
`fixture` with a real value in the live pipeline) -- a candidate for a further pass, not
attempted here since it doesn't block the upcoming multi-object work.
